## 1. 视觉总纲

### 1.1 一句话

> **深藏蓝的夜里，一团青绿色的众智在汇聚。冷，但有生命力。**

三个关键词，对应三个可验证的约束：

| 关键词 | 含义 | 可验证的约束 |
|---|---|---|
| **冷** | 深色底、克制的用色、几何化排版 | 页面主体色占比 ≥60% 为白/浅底；深色只出现在 Hero、CTA、深色内页头 |
| **有生命力** | 粒子、流体、渐变在动 | 动效来自真实物理感（curl noise 向心汇聚），不是循环 GIF |
| **不喧宾夺主** | 3D 是气质不是信息 | 任何一条信息都不能只有 3D 形式存在；降级后信息完整 |

### 1.2 与竞品的视觉区隔

> 依据 `docs/05-全国OPC社区与商业楼宇平台竞品审查.md`：

| 竞品常见做法 | 集智的做法 | 为什么 |
|---|---|---|
| 满屏炫光 / 大面积高饱和渐变 | 深藏蓝底 + **左侧文案区压暗** + 粒子让到右侧 | 首屏文字必须是最强信息，不能被背景吃掉 |
| 通用「科技蓝」配色 | 品牌色板**取自 logo.svg 实测**，含青绿点缀 | 竞品几乎都是纯蓝+白，色板本身就是识别度 |
| 网格/粒子背景平铺全站 | 3D 只在**首页**（首屏雕塑 + 整页「数字海洋」fixed 背景层），内页用静态网格 | 全站 3D 会拖垮性能并稀释首屏的冲击；波海层仅在首页深色区透出，白区被实心底遮盖 |
| 滚动视差堆叠 | 一次性的区块揭示，且**服务端可见** | 视差在移动端体验差，且伤害内容可读性 |

### 2.2 硬规则

| 规则 | 说明 |
|---|---|
| **禁止彩虹色** | 所有 `colors` 数组、所有渐变只能取自上表 |
| **深浅配比** | 单页深色面积 ≤ 40%（首页 Hero + 底部 CTA 两处） |
| **正文对比度** | 正文对底色 ≥ 4.5:1；大字 ≥ 3:1 |
| **深底上的字** | 白/白 70–85% 透明度分层，不用纯白铺满 |
| **一个强调色** | 每屏最多一个品牌蓝实心 CTA，其余用描边或文字链 |

### 2.3 可读性约束（2026-10-20 实测后新增）

Lighthouse 实测发现：品牌主色**在浅底上直接当小字用达不到 WCAG AA**。实测对比度：

| 色 | 白底 | surface 底 | 判定 |
|---|---|---|---|
| `--color-brand-blue` `#1D7FBA` | **4.38:1** | 4.09:1 | 小字 ❌（差 0.12）、大字 ✅ |
| `--color-brand-cyan` `#1AA8D3` | **2.77:1** | 2.60:1 | 小字 ❌、大字 ❌ |
| `--color-brand-teal` `#57B6A5` | **2.45:1** | 2.30:1 | 小字 ❌、大字 ❌ |
| `--color-brand-blue-deep` `#0968AB` | **5.87:1** | 5.49:1 | 小字 ✅ |
| `--color-brand-navy` `#142F59` | 13.3:1 | 12.4:1 | ✅ |
| `--color-ink-3`（旧 `#7B8494`） | 3.56:1 | **3.56:1** | 小字 ❌ → 已调整为 `#5F6878`（5.3:1） |

**因此确立三条硬规则**：

1. **浅底小字与填充按钮统一用 `--color-brand-blue-deep`**（取品牌渐变起始色 `#0968AB`，非臆造新色）。主蓝 `#1D7FBA` 保留给边框、图标、大字（≥24px）与渐变端点。
2. **亮青与青绿不用于浅底文字**，只出现在深色区、3D 粒子与渐变里——深底上二者对比度分别为 4.79 / 5.40，合规。
3. **白字承载的色块不能用青绿/亮青**：白字在 `#57B6A5` 上仅 2.45:1。承载白字的渐变一律收敛到 `#0968AB → #0E3769`（白字 ≥5.87:1）。`.text-gradient` 的端点同步收敛为 `#0E3769 → #0968AB → #1D7FBA`。

**结果**：Lighthouse 可访问性由 **96 分（2 项失败）提升到 100 分（0 失败）**，Best Practices / SEO / Agentic Browsing 同为 100。

### 2.4 卡片与层级体系（2026-10-20 审计后新增）

> 此前 §6 的组件规范写的是「**所有卡片统一 16px 圆角 + `--shadow-card`**」——
> 这条规范本身就是「AI 生成感」的**制度性根因**：它把全站拉平成同一种卡片，
> 于是「每一张卡都会抬起来」「默认态就带阴影」「没有一张安静的卡」。
> 本节把规范改成**两档制**。

#### 两档卡片

| 档 | 外观 | 用途 | 数量约束 |
|---|---|---|---|
| **主卡** `feature` | `rounded-xl` + 1px 描边 + **2px 品牌色顶边**（`border-t-2 border-t-brand-blue-deep`）；hover 只改边框与底色 | 转化面、每屏最重要的对象 | **连续排在最前**形成「精选区」；长列表用「前 N 主 + 其余次级」表达精选与长尾 |
| **次级卡** `default` | `rounded-xl` + 1px 描边 + **无阴影**；hover 只改边框与底色 | 列表条目、支撑模块、次级面板 | 不限 |

实现：`src/components/ui/Card.tsx` 的 `variant="feature" | "default"`。

#### 圆角 scale（每视口最多同时出现 2 档）

| 档 | Token | 值 | 用途 |
|---|---|---|---|
| 标签 / 输入框 | `--radius-tag` | 4px | `rounded` |
| 按钮 / 导航 | `--radius-control` | 8px | `rounded-lg` |
| **次级卡 / 面板** | `--radius-panel` | 12px | `rounded-xl` |
| **主卡 / 区块容器** | `--radius-card` | 16px | `rounded-2xl` |
| 特大 | — | 24px | **仅** 首页深底 CTA |

#### 阴影 scale（默认描边，阴影是奖励不是标配）

| 用途 | 值 |
|---|---|
| **所有卡片** | **无阴影** + 1px `border-[var(--color-line)]`；主卡靠 2px 品牌色顶边区分 |
| 主卡 | **不用阴影**，改用 2px 品牌色顶边（2026-10-21 UI 优化轮次改向） |
| hover / 浮层 | `--shadow-lift` |
| 下拉浮层 | `--shadow-overlay`（新增） |

#### 其它三条去 AI 感的规则

1. **区块标题默认左对齐**（`SectionHead` 的 `align` 默认改为 `'left'`）；需要居中的显式传 `align="center"`。过去 12 处区块标题有 9 处是「居中大标题 + 一排同款卡」，滚动时节奏完全不变。
2. **eyebrow 用纯文字小标**，不用「圆角胶囊 + 描边」——后者是模板站最强的信号。样式：`text-[12px] font-medium tracking-[0.18em] text-[var(--color-brand-blue-deep)]`。
3. **渐变文字全站只保留 1 处**（404 页）。首页主标题改用纯色 `--color-brand-blue-deep`。

#### 明确不动的（动了反而降低质感）

- 导航主 CTA 的**胶囊形**（全站唯一主行动点，胶囊强化行动性）
- 语义为「可选标签」的筛选 chip（胶囊正确）
- 品牌徽记容器、状态徽章 `rounded-md`、`h-1.5 w-1.5` 装饰圆点、链路节点圆
- 深底上的玻璃拟态（`PageHero` 光晕、滚动后的玻璃导航）——层次手段，不是滥用

### 2.5 UI 优化轮次的设计转向（2026-10-21）

> 详细基线与验收见 `docs/07-UI优化与性能验收.md`。本节只记录**规范层面的变更**。

| 项 | 变更前 | 变更后 | 理由 |
|---|---|---|---|
| 卡片 | 两档（16px+阴影+抬升 / 12px+描边） | **单一规格**：12px 圆角 + 1px 描边 + **无阴影**；`feature` 变体用 **2px 品牌色顶边** | 阴影与抬升是「AI 生成感」的主要来源之一；层级改由**排版、位置与顶边**承担 |
| 首页 Hero | 大标题居左 + 右侧粒子 | **kicker（品牌名）+ 编辑式大标题 + 右侧粒子艺术装置 + 底部事实条** | 首屏先说清「是谁」，再说「做什么」 |
| 区块标题 | `SectionHead` 组件（eyebrow 胶囊/纯文字 + 标题 + 描述） | 首页改用**带编号**的 `.section-eyebrow`（`01 / 八大赋能`）+ 裸 `<h2>`；内页仍用 `SectionHead` | 编号让区块顺序可读，是编辑排版的做法 |
| 指标条 | client component + framer-motion 计数动画 | **server component 静态输出**（数字与单位分色） | 去掉一整个客户端依赖与动画；SSR 直接给出最终值 |
| 3D 画布 | 2 个（Paper 背景层 + three 粒子层） | **1 个**（同一 WebGL 上下文内合并） | 少一个上下文、少一份显存与一次状态同步 |
| Three.js 加载 | 始终 `next/dynamic` 异步块 | **唯一的懒加载边界**；无 WebGL2 / 减弱动效 / 省流量时**根本不请求** | 实测降级场景下 `performance.getEntriesByType('resource')` 中无 three chunk |
| 指针交互 | `setState` 每帧更新 → 触发整树重渲染 | **`pointerRef`**，逐帧只读 ref | 消除每帧的 React 更新 |

## 4. 3D 粒子动效规范

### 4.1 场景清单

| 场景 | 位置 | 技术 | 强度 | 目的 |
|---|---|---|---|---|
| **D-01 众智星云** | 首页 Hero | Three.js + R3F，自写 GLSL 粒子 + Paper `MeshGradient` 背景 | 中 | 建立第一眼科技感与「集众智之力」的意象 |
| **D-02 能量环** | 首页八大赋能 | **改为链路节点点亮**（CSS，无 Canvas 成本） | 低 | hover 赋能卡片时对应链路节点点亮 |
| **D-03 卡片微动效** | 智能体/供需卡片 | CSS `perspective()` + 径向渐变扫光 | 极低 | 提供触感，不占 GPU |
| **D-04 指标条** | 首页指标条 | **静态输出**（server component，无客户端计数与动画）；数字与单位分色排版 | 低 | 强调密度，且不引入 framer-motion 依赖 |
| **D-05 链路流光** | 八大赋能区 | CSS 渐变流动线 | 低 | 表达「一条链」而非「八个格子」 |
| **D-06 数字海洋** | 首页整页（fixed 背景层） | Three.js + R3F 自写 GLSL 点阵波海（与 D-01 同一 three chunk，**零新增依赖**） | 中低 | openhex wave-grid 模式：全页呼吸感的整体动效底，Hero 与底部 CTA 透出、白区遮盖 |

> **D-02 修订记录（2026-10-20）**：原方案是 Paper `PulsingBorder` / `DotOrbit` 的**独立环状能量环**（8 节点围一圈）。修订为**在既有链路上做 hover 联动**——hover 赋能卡片 → 对应链路节点放大高亮；`集智商学院` 与 `企服超市` 不占独立节点，合并为链路下方的「贯穿全链 · 人才补齐 + 后台支撑」条。
>
> **修订原因**：竞品审查（`docs/05` §6.2）的核心结论是「**八大赋能是一条链，不是八个功能**」。环状结构在视觉语义上表达「并列/循环」，与该定位叙事直接冲突；且 22px 的节点上放 Canvas 动效收益极低、成本不低。**交互意图（hover 点亮对应节点）完整保留，实现见 `src/components/sections/EmpowerChain.tsx` 与 `EmpowerSection.tsx`。**

> **D-06 修订记录（2026-10-21 新增）**：参照 openhex.tech 的 wave-grid 背景，为首页新增整页「数字海洋」fixed 背景层（`WaveField`，z-index:-1 落在所有静态区块背景之下）。**分工**：D-01 雕塑仍是首屏焦点，波海是全页氛围底——多组低频行波叠加（速度 ≤0.18 rad/s = 呼吸感），波峰亮波谷暗，指针划过激起涟漪（pointer:fine）。**节奏由 HomeFx ScrollTrigger 驱动**：滚出 hero 压暗至 0.12，底部 CTA 复现至 0.7。**上下文策略**：仅 desktop high/medium 创建第二个 WebGL 上下文（共享 three chunk，体积增量≈0）；low/static/reduced-motion 档显示纯 CSS 静态海面（`StaticWave`），移动端维持单上下文给 D-01。实现见 `src/components/three/WaveGrid.tsx` 与 `WaveField.tsx`。

> 库选型依据见 `docs/04-shader选型指南.md`：`shaders`（WebGPU，727.5KB gzip，无 WebGL 降级）**本期不用**。

### 4.2 D-01 众智星云 详细规格

**视觉**：深藏蓝夜空 + 中心星云 + 大量微粒**向心汇聚**，暗示「众智汇聚」。冷静、有层次，不炫技。

**实现**：

| 层 | 做法 |
|---|---|
| 背景层 | Paper Shaders `MeshGradient`（WebGL/GLSL），品牌四色，`distortion=0.82` `swirl=0.16` `speed=0.25` |
| 粒子层 | `THREE.Points` + `BufferGeometry`（N 顶点 + 自定义 `aSeed` 属性） |
| 粒子运动 | **顶点着色器**内完成：curl noise 场推力 + 向心引力 + 每粒子独立相位。CPU 每帧只更新 `uTime` 与 `uPointer` |
| 粒子外观 | 片元着色器软圆点（`gl_PointCoord` 距离衰减）+ `AdditiveBlending` |
| 颜色 | `brandRamp()` 按半径在 深藏蓝→主蓝→青绿→亮青 间插值 |
| 构图 | 粒子组整体右移 `x=+1.5`，让出左侧文案区 |
| 暗部 | Hero 上叠一层 100° 线性渐变：左侧 `rgba(10,37,71,.96)` → 78% 处透明 |

**参数**（实测调优后的最终值）：

| 参数 | 值 | 说明 |
|---|---|---|
| 粒子数 | high **12000** / medium 6000 / low 2500 / static 0 | 初版 32000 过密、压过文字，已下调 62% |
| 点尺寸 | `(2.6 + seed*5.4) * dpr * (5.2 / dist)` | |
| Alpha | `soft * (0.10 + bright*0.26) + core * 0.16` | |
| 颜色增益 | `col * (0.62 + core*0.75)` | |
| DPR | ≤1.5（移动 ≤1.25） | |
| 指针引力 | `p.xy += uPointer * 0.07` | 轻微，不改变构图 |
| 自转 | `scene.rotation.y += delta * 0.012` | |

### 4.3 降级链（四级 + 无 JS 兜底，逐级已留证）

> **2026-10-20 实测修订**：原规格的 ③「仅 three（WebGL1）」**不可实现**，已合并进静态档。详见下方修订记录。

| 级别 | 条件 | 表现 | 实测结果 |
|---|---|---|---|
| ① 完整 | WebGL2 可用 + 设备 high/medium | MeshGradient 背景 + 12000 / 6000 粒子 | tier=high，particles=12000，2 个 canvas，控制台 0 错误 |
| ② 轻量 | WebGL2 可用但设备 low（移动端 / deviceMemory≤4） | MeshGradient 降参数 + **2500** 粒子 | iPhone UA → tier=low，particles=2500，2 个 canvas |
| ③ 静态 | **WebGL2 不可用（含"仅 WebGL1"的设备）** | 静态品牌渐变 + 静态星点（CSS，无 WebGL） | 禁用 webgl2 上下文 → tier=static，0 canvas，静态兜底渲染，H1 与 CTA 可见 |
| ④ 静态 | `prefers-reduced-motion` / `saveData` / deviceMemory≤2 | 同 ③ | 模拟减弱动效 → tier=static，0 canvas，静态兜底渲染，H1 可见 |
| ⑤ 无 JS | JS 异常 / 未执行 | **SSR HTML 内已含**静态渐变 + 文案 + CTA | 服务端 HTML 逐项自检 9/9 通过，体积 88.7KB，**0 处 `opacity:0` 残留** |

**硬约束**：任何一级降级下，**Hero 文案、指标条、CTA 必须完整可见**（上表「实测结果」列即为逐级留证）。

#### 4.3.1 修订记录：③「仅 three（WebGL1）」不可实现（2026-10-20 实测）

**原规格**：③ 设想在只有 WebGL1 的设备上丢掉 Paper 背景层、只保留 three 粒子层（简化 shader）。

**为什么不可实现**：

- **three r163 起移除了 WebGL1 支持**（`WebGL1Renderer` 已删除）。实测 `three@0.169.0` 的构建产物里 `webgl2` 出现 3 次、**`webgl1` 出现 0 次**，且硬编码 `const contextName = 'webgl2';`。
- Paper Shaders 同样是 GLSL ES 3.00（WebGL2）。

→ 因此「仅 three（WebGL1）」这一档**在物理上不存在**：WebGL1-only 设备上 three 与 Paper 都跑不了，正确行为是**直接落到静态档**。

**更严重的是：原实现在这类设备上不是"没有 3D"，而是"把整页炸掉"**。实测（禁用 webgl2 上下文模拟 WebGL1-only）：

```
THREE.WebGLRenderer: Error creating WebGL context.
Uncaught Error: Error creating WebGL context.
```

根因是 `detectWebGL2()` 写成了 `getContext('webgl2') ?? getContext('webgl')` —— **把 WebGL1 也判为可用**，于是挂载 three → 抛错 → 异常沿 React 树冒泡 → **整个 Hero 子树被卸载，连带 H1、副标、简介与 CTA 全部消失**（实测 `h1Visible: false`、0 个 canvas、静态兜底也没渲染）。

这与 §1.1「任何一条信息都不能只有 3D 形式存在」和 §4.3 硬约束直接冲突，且**正好命中竞品审查 R5 点名的微信内置浏览器 / 老旧设备场景**。

#### 4.3.2 修法：两道防线

| 防线 | 位置 | 作用 |
|---|---|---|
| **① 严格 WebGL2 探测** | `src/components/three/quality.ts` | `detectWebGL2()` 只认 `'webgl2'`；新增 `detectWebGL1()` 仅作诊断。无 WebGL2 → 直接 `tier = 'static'`，**根本不挂载 three** |
| **② 错误边界** | `src/components/three/ThreeErrorBoundary.tsx` | 覆盖探测**无法预见**的失败：着色器编译失败、上下文丢失、驱动黑屏、显存不足、Paper 组件内部异常。3D 抛错 → 降级为静态背景，**内容一律不受影响** |

**第二道防线的实测**：用脚本让「能力探测通过、但渲染器创建时抛错」，结果 `tier=static`、0 canvas、静态兜底渲染、**H1 与 CTA 仍可见** ✅。

**顺带修复**：原先 `HeroScene` 用 `next/dynamic` 的 `ssr: false`，导致**静态兜底层根本不在服务端 HTML 里**——无 JS 时首屏背景是一片纯色。现已改为**允许 SSR**（three/Paper 子块仍是 `ssr: false`），服务端 HTML 逐项自检 9/9 通过。

**可观测性**：`HeroScene` 根节点暴露 `data-3d-tier` 与 `data-3d-particles`，使降级档位与实际粒子数**可被外部脚本与自动化测试直接读取**——这是"逐级必须留证"得以自动化的前提。

### 4.4 性能预算

| 指标 | 预算 | 实测/手段 |
|---|---|---|
| 3D JS 体积 | ≤270KB gzip | three+r3f **251.6KB** + paper **11.6KB**（esbuild 实测） |
| 首屏 3D 挂载 | LCP 之后 | `next/dynamic` + `ssr:false` + 空闲挂载 |
| 帧率 | 桌面 60fps / 移动 ≥30fps | `useAdaptiveQuality` 滑动窗口采样，<45fps 自动降档 |
| 视口外 | GPU 占用为 0 | `IntersectionObserver` + `frameloop='never'` |
| 内存 | 长滚动不涨 | 卸载时 `dispose()` geometry/material |

### 4.5 动效节奏（页面级）

| 元素 | 动效 | 时长/缓动 | 触发 |
|---|---|---|---|
| Hero 粒子 | 持续 | 常驻 | 进入视口 |
| 区块揭示 | opacity 0→1 + translateY 18→0 | 600ms `cubic-bezier(.2,.8,.2,1)` | 首次进入视口 |

> `globals.css` 曾把 `button, input, textarea, select { font: inherit; }` 写在层级外 ——
> Tailwind v4 里**未分层样式的优先级高于 `@layer utilities`**（CSS Cascade 5），
> 于是 `text-[14px]` 这类字号工具类对表单元素**全部失效**：实测 `input` 算 16px、`div` 算 14px，
> 作者写下的字号被静默吞掉。把它收进 `@layer base` 后工具层才能正常覆盖。
> 移动端另有硬约束：表单控件字号 **≥16px**（iOS Safari 聚焦小于 16px 的输入框会自动放大整页），

## 7. 可访问性

| 项 | 要求 |
|---|---|
| 动效降级 | `prefers-reduced-motion: reduce` → 全部动效关闭，3D 降级为静态 |
| 3D 语义 | 3D 容器 `aria-hidden="true"`，信息不依赖动效传达 |
| 焦点 | `:focus-visible` 2px 亮青描边 + 2px 偏移 |
| 键盘 | 下拉菜单、移动端抽屉、筛选 chips、表单全部键盘可达 |
| 跳转链接 | 页面首个可聚焦元素是「跳转到主要内容」 |
| 色彩 | 正文对比度 ≥4.5:1 |
| 语义 | 每页一个 H1；表单 label 与 input 关联；错误信息 `role="alert"` |
| 触控目标 | 可点击元素 ≥24×24（本站规范 ≥40×40）；**输入框本体要撑满容器**（`h-full`），否则 40px 容器里的 input 只有 23px 高，容器上下缘是点不到的死区 |
| 小字压暗 | **禁止用 `opacity` 压暗小字**：同一个色值要同时压得住白底与蓝底，压暗后必然有一边不过 AA。实测筛选计数用 `opacity-70` 时白底 3.71:1、蓝底 3.72:1，Lighthouse 判失败；改为按选中态分别给色（浏览器实测：白底 `--color-ink-3` 5.62:1，蓝底 88% 白 4.93:1） |
