# 动态内容契约（P1：新闻 + 活动列表动态化）

> 本文件是并行实施的**唯一契约**：构建管线（Worker B 生产）、运行时层（Worker C 消费）、
> 迁移脚本（Worker A）三方都以本文为准。类目常量与占位符名的代码事实源：
> `src/lib/opc/taxonomy.ts`。
>
> 2026-10-26 起站内另有一套**区块级**运行时化（统计墙/伙伴墙/课程卡/智能体目录/供需卡——
> 无占位符、在烘焙快照 HTML 上就地替换），契约见 `docs/17-区块运行时化契约.md`；
> 本文件只覆盖新闻/活动列表的占位符模式。

## 1. 占位符与兜底产物

- 构建管线在 `generated/pages.json` 的 `/newslist`、`/activitylist` 页面 HTML 中，
  把 `.news-list` / `.activity-list` 容器的全部卡片替换为纯文本占位符：
  - `/newslist` → `__OPC_NEWS_LIST__`
  - `/activitylist` → `__OPC_ACTIVITY_LIST__`
- 同步产出 `generated/list-cards.json`（构建期快照兜底，形状固定）：

```json
{ "news": "<88 张 news-item 卡片的连续 HTML 串>", "activities": "<22 张 activity-item 卡片的连续 HTML 串>" }
```

- **兜底串必须与改动前烘焙在 pages.json 里的卡片逐字节一致**（含 `data-v-*`、本地图床 `/opc/assets/...`）。
- 运行时注入规则：DB 查询成功 → 渲染 DB 卡片；未配置库/查询异常 → 注入兜底串；
  shell 中占位符不存在（旧产物兼容）→ 原样返回不注入。

### 渲染器字段映射（news_posts → 卡片）

| 卡片槽位 | news-item | activity-item | 来源 |
|---|---|---|---|
| 根节点 | `class="news-item"` | `class="activity-item"` | — |
| data-opc-id | slug 的数字部分（`opc-N`→N）或 slug | 同左 | slug |
| data-opc-route | `/newsdetail?id=<data-opc-id>` | 同左 | — |
| data-opc-category | `""` | 类目名（如 `活动`） | category |
| 图片 | `.news-image img`，`loading="lazy" decoding="async"` | `.activity-image img` | cover_url（无则用占位图 `/opc/visual/reference-city-blue-960.webp`） |
| 标题 | `.news-title` | `.activity-title` | title |
| 摘要 | `.news-summary` | activity 的简介段 | summary |
| 日期 | `.news-date`（YYYY-MM-DD） | `.fas.fa-calendar` 旁文本 | published_at |
| 徽标 | — | `.activity-badge` 固定文案 `精彩活动` | — |

- 全部文本经 HTML 转义；`data-v-83dfbbe5`（news）/`data-v-0bb519df`（activity）属性照抄模板。
- ReplicaInteractions 的筛选/加载更多按 DOM 契约工作：卡片是 `.news-list`/`.activity-list` 容器直接子节点、
  带 `data-opc-id`、匹配 cardSelector；**不得改变类名或层级**。

## 3. 数据映射（迁移脚本：快照 → news_posts）

- 来源：`scripts/opc-source/public-content.json` 的 records，`category_id ∈ {10,16}`（10→news、16→activity）
- slug：`opc-<原id>`；title：rebrand 后标题（品牌替换规则同 `build-opc-content.py` 的 `rebrand()`，移植到脚本）
- summary：`subtitle_list` 中 `sort==1` 的 content；body：`record.content` 数组（`sort != -1`）按 sort 升序的正文片段，每项可为纯文本或富文本 HTML
- category：10→`资讯`、16→`活动`；status：`published`；author：`集智 AI`
- published_at：`create_time`（epoch 秒）→ ISO 日期；cover_url：`head_image[0].url` 经 `asset-map.json` 映射为本地 `/opc/assets/...`
- 幂等：ON CONFLICT(slug) DO NOTHING；`--dry-run` 只打印计划

## 4. /newsdetail?id= 解析顺序（运行时）

1. id 为数字 N → 先查 DB slug=`opc-N`，再回落遗留 `generated/details.json[N]`
2. id 为 slug 形态 → 查 DB 该 slug
3. DB 正文（body 数组）按片段注入 `article-shell`：纯文本转义为 `<p>`；富文本 HTML 经 `sanitize-html` 允许列表净化后保留标签、图片与安全排版，移除脚本、事件属性、危险协议和协议相对 URL。标题与日期始终转义。
4. 都没有 → 404

## 5. 发布联动矩阵（revalidatePath）

新闻/活动发布、下架、删除时失效：`/news`、`/news/[slug]`、`/newslist`、`/activitylist`、`/`、`/sitemap.xml`

`/newsdetail?id=` 条目改读 DB 已发布文章（id 用 data-opc-id 同款取值），无库时回落 `listings.json`。
