# 全站复刻与参考站快照管线（2026-11-10 起）

> 本文件是 2026-11-10「按参考站做全站复刻替换」后的**总契约**。
> 代码事实源：`scripts/fetch-opc-reference.mjs` → `scripts/build-opc-reference.mjs`
> → `src/lib/opc/generated/pages.json` → `src/lib/opc/blocks-runtime.ts` /
> `src/lib/opc/news-runtime.ts`。
> 契约测试：`test/opc-content.test.ts`、`test/dynamic-blocks.test.ts`、
> `test/opc-news-runtime.test.ts`。

## 0. 一句话

公开站的**内容与素材**来自参考站 https://jizhi-ai-opc.app.workbuddy.host/ 的快照；
**动态维护能力**（后台可编辑的智能体 / 课程 / 动态 / 供需 / 统计 / 伙伴 / 线索）
继续由 Supabase 承担，运行时把快照里的对应容器换成后台数据。

## 1. 与旧架构的差异（2026-10 版本 → 2026-11-10 版本）

| 维度 | 旧（opcstore 复刻） | 新（参考站复刻） |
|---|---|---|
| 事实源 | `scripts/opc-source/*.json`（opcstore 抓包） | `scripts/opc-reference/`（参考站抓取） |
| 编译 | `scripts/build-opc-content.py`（Python，1829 行） | `scripts/build-opc-reference.mjs`（Node，零依赖） |
| 页面数 | 18 页 + 158 篇详情 + 233 工具 | 10 页（参考站全部页面） |
| 路由 | /newslist /center /traffic /work /starproject… | /news /academy /growth /health /empower…（与参考站一致） |
| 导航 | 8 项 + 3 个下拉 | 9 项（与参考站逐项一致） |
| 视觉 | 自研「科技蓝」设计层（opc-*.css，3300 行） | 参考站样式表 + `.opc-site` 作用域前缀 |
| 区块定位 | 按 CSS 类名猜锚点（`div.hero-stats-row` 等） | 编译期打 `data-opc-block="<marker>"` 标记 |
| 智能体目录 | 烘焙 233 卡 + 分类 chips | 参考站 agents.js 的 233 条 → `agents` 表 |

冲突。`src/styles/` 现在只剩 `globals.css`（后台与原生页用）与 `admin-rich-text.css`。

## 2. 管线

```
scripts/fetch-opc-reference.mjs          # 抓参考站（需 sharecode）→ scripts/opc-reference/
        │  pages/*.html + assets/{css,js,img}
        ▼
scripts/build-opc-reference.mjs           # 编译
        │  ① 抽 <main>（页头/页尾由 React 外壳渲染）
        │  ② 链接改写：.html → 站内路由；assets/ → /opc/reference/
        │  ③ 清理：编辑器节点属性、随机 id、内联脚本
        │  ④ 净化：sanitize-html 白名单（保留 SVG 与内联样式）
        │  ⑤ 打 data-opc-block 标记
        │  ⑥ CSS 作用域化：所有选择器加 .opc-site 前缀
        ▼
src/lib/opc/generated/pages.json         # 路由 → { title, html }
public/opc/reference/main.css            # 作用域化后的参考站样式
public/opc/reference/extension.css       # 我们补的扩展样式（参考站自身缺 29 个类）
public/opc/reference/img/*               # 参考站图片素材
```

常用命令：

```bash
pnpm reference:fetch     # 重新抓取参考站（抓取失败不影响已入库快照）
pnpm reference:build     # 重新编译产物（改了 markDynamicBlocks / 白名单后必跑）
pnpm reference:seed      # 把参考站内容灌进后台表（幂等：已有数据就跳过）
```

## 3. 路由与导航

公开路由（`src/lib/opc/routes.ts` 的 `replicaPaths`）：

```
/  /about  /health  /empower  /market  /growth  /academy  /news  /newsdetail  /apply  /agent
```

- 八大赋能的 8 个详情页 `/empower/[slug]` 是**原生路由**（DB 驱动的 empower_modules 表），
  不在复刻快照内；导航里不出现（参考站的「八大赋能」是单页）。
- 旧 URL 全部 308 收敛（`next.config.ts` 的 `redirects()`）：
  `/center→/academy`、`/traffic→/growth`、`/newslist→/news`、`/activitylist→/news`、
  `/join→/apply`、`/news/:slug+→/news`。
  ⚠️ `/news/:slug+` 必须用 `+`（一段及以上）而不是 `*`，否则 `/news` 会 308 到自身形成环。

导航（`src/lib/site/navigation.ts` 的 `publicNavigation`，9 项）与参考站逐项一致：
首页 / 关于集智(集智简介#intro、发展历程#history、服务对象#who、生态伙伴#eco) /
大健康+AI / 八大赋能 / 供需发布 / 流量赋能 / 集智商学院 / 社区动态 / 申请入驻(CTA)。

## 5. 表单直连后台（相对参考站的刻意差异）

参考站的两个表单都只写 localStorage（演示态）。本项目改为**直连后台**：

| 表单 | 位置 | 提交 | leadType |
|---|---|---|---|
| 入驻意向表 | `/apply`（`#joinForm`） | `POST /api/leads` | `apply` |
| 供需发布（需求/供给双 Tab） | `/market`（`#sdNeed` / `#sdGive`） | `POST /api/leads` | `market` |

- 入驻表单的字段映射（申请主体类型 → `subjectType`、团队人数 → `teamSize`、
  需要哪些赋能 → `message`、同意条款 → `agreeTerms`）见 `src/lib/opc/form-payload.ts`。
- 供需表单提交后**仍然生成可复制的发布卡片**（参考站的交互不变），只是同时进后台线索池。
  （注：「社区供需榜」展示模块已于 2026-11-10 下线，`/market` 前台不再展示已上架的供需卡；
  后台「供需发布」模块与 `market_items` 表保留。）

## 6. 样式作用域

参考站样式表含全局重置（`body`/`h1..h5`/`p`/`ul`/`img`/`a`/`button`…），
直接整份引入会污染后台（Tailwind）。因此编译期给**所有选择器**加 `.opc-site` 前缀：

- `:root` → `.opc-site`（变量定义在作用域根，子元素继承）；
- `body` → `.opc-site`；`html` 保持全局（`scroll-behavior` / `scroll-padding-top` 对全站无害，
  且锚点偏移依赖它）；
- `@keyframes` / `@font-face` 内部不加前缀。

作用域根是 `src/components/layout/SiteChrome.tsx` 里的 `.opc-site`（公开站外壳）；
后台与运营区是 `.opc-independent`，**完全不吃**参考站样式。

参考站样式表自身有 29 个类**没有样式**（课程卡、就业流程、入驻要求、增长率墙、
新闻配图与转载说明等）——在参考站上这些区块是裸的。本项目用
`public/opc/reference/extension.css` 按同一套 token 补齐，并新增动态区块样式
（生态伙伴墙、回到顶部），同时把字号抬到 ≥12px、触控区补到 ≥24px。

## 6.1 编译期适配层（快照 → 站点）

参考站快照是**忠实抓取**，但有四处必须在本项目语境下修正 —— 这些修正统一放在
`scripts/build-opc-reference.mjs` 的编译期（快照本身保持原样，便于日后比对）：

| 修正 | 原因 |
|---|---|
| `promoteCheckboxChips` | 参考站的多选 chip 用 `<span>` 包裹 → **点文字不勾选**，勾选框仅 15px。提升为 `<label>` 后整块可点、触控区达标 |
| `promoteAgreeCheckbox` | 同上，「同意条款」勾选框 |
| `correctMarketFormNote` | 参考站原文说「静态演示版：内容不会上传服务器，只在您本机生成」—— 对参考站成立，**对本站不成立**（表单直连 `POST /api/leads`），照抄会对用户说假话 |
| `moveJoinOkOutsideForm` | 参考站新版把提交成功提示放在 `<form>` **内部**；本站成功后隐藏表单会连带隐藏提示框 → 移到表单外并补 `role="status" aria-live="polite"` |
| `normalizeBooleanAttrs` | `hidden=""` 这类**空值布尔属性**会被 sanitize-html 直接丢弃（其 `nonBooleanAttributes` 列表含 `hidden`）→ 规范成 `hidden="hidden"` |
| `removeNewsSubscribeCard` | 参考站 /news 列表底部有一张「资讯由社区运营团队维护……留下联系方式」的订阅提示卡，用户 2026-11-10 要求删掉该布局（该卡片全站仅此一处，精确按内联样式串定位） |

### 6.2 extension.css 必须对着**当前快照结构**写

参考站快照页（`scripts/opc-reference/pages/*.html`）里的**内联 `<style>` 会被编译管线整段剥掉**
（`nonTextTags` 含 `style`）。这些类在参考站上「有设计、没样式表」，唯一的落地处就是
`public/opc/reference/extension.css` —— 所以它对这类类是**权威设计源**，不是可以自由发挥的地方。
**权威依据是快照页自己的内联 `<style>`**，写错结构就会连带写错色值。

2026-11-10 实例（`/growth` 成长路径「实训学员 → … → 项目合伙人」）：

- extension.css 把 `.gw-flow` 写成「深色块内的数字栅格」（`display:grid` + `repeat(4,1fr)`
  + 近白字 `rgba(226,238,252,.78)`），但当前快照 HTML 里它是**浅色 section 内的平级胶囊流程条**
  —— 字色与底色几乎同色，**文字完全不可见**；4 列栅格还把 6 步 + 5 箭头拆成 4 列、行尾断箭头。
- 同源问题同批修掉：`.gw-cap`（`--mint` #3FE0F8 压浅底 = 1.46:1）、`.gw-note`（`rgba(200,216,236,.72)` 压浅底）。
- 已按参考站内联样式还原：白色胶囊 + `--navy` 字 + `--gray` 箭头，`display:flex; flex-wrap:wrap`。

**验收口径**（不要靠肉眼读截图）：

- `npm run opc:audit:contrast` 做**真实像素采样**（滚动→截图→按 `Range.getClientRects()` 定位→
  剔除字形像素→取众数当背景→算 WCAG 比值），比静态推算可靠。
- 文字不可见的**指纹**是「剔除字形像素后背景桶为空」——脚本输出 `bg=n/a`、对比度算不出来，
  说明前景色与背景色几乎相同。
- ⚠️ 该脚本的 `PAGES` 清单是**手写**的，新页面不在清单里就**不会被测到**；
  `/growth` 当时就不在清单中（本轮是另写定点探针补测的）。加页面要同步改清单。

## 7. 安全口径

- 编译期净化：标签/属性白名单 + 内联样式逐属性正则 + 协议白名单（https/mailto/tel）；
  `<script>`、事件属性、`data-page-node-id` 一律剥离；SVG 保留（`viewBox` 等大小写敏感属性
  通过 `parser.lowerCaseAttributeNames = false` 保住）。
- 运行时：所有 DB 文本经 `escapeText`；图片仅 https 或本站根相对路径；智能体外链仅 https。
- 参考站 CSS 原文第 777 行有一个**多余的 `}`**（浏览器容错通过，postcss 会报错），
  编译期由 `repairCss()` 做括号配平修复。

## 8. 已知边界

- **Supabase 项目当前不可用**（`workspace or branch is not ready`）时，
  所有动态区块为空、`/api/leads` 回落「本地开发模式」；参考站内容需先跑
  `pnpm reference:seed` 才能在前台与后台看到。
- `pnpm reference:seed` 是**幂等**的：某张表已有数据就整表跳过，不覆盖运营后续修改。
- Next ISR 构建缓存跨构建复用：`.next/cache` 内的 ISR 页在 revalidate 窗口内不会被下一次
  `next build` 重渲染——**改库后验证必须删构建目录全新构建**。
- **`pnpm dev` 下复刻页的交互会「假死」，交互类问题必须用生产构建验证。**
  复刻页主体是 `dangerouslySetInnerHTML` 注入的烘焙 HTML，交互靠
  `src/components/opc/ReferenceInteractions.tsx` 在 `useEffect` 里**命令式**挂监听器；
  两个 dev 专属陷阱会让监听器全部失灵（表现：Tab 不切换、表单不校验、提交退化成原生 GET 刷新）：
  1. **`.next` 缓存复用** → 客户端 bundle 陈旧（改过 `src/` 也不生效，chunk hash 不变）；
  2. **Fast Refresh 重建** → React 重新渲染时把烘焙 HTML 换成一组**新节点**，
     旧节点上的监听器随之失效（`.totop` 在 layout 里，不受影响，容易误判为「脚本没跑」）。
  生产构建没有这两条（StrictMode 双调用只在 dev），所以**同一份代码 dev 坏、生产好**是常态。
  验证姿势：`NEXT_DIST_DIR=.next-prod pnpm build` + `NEXT_DIST_DIR=.next-prod pnpm start -p 3001`，
  用独立 distDir 另起端口，不影响 dev 服务。
