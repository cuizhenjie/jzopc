### 2.1 边界原则

1. **浏览器不直连数据库**。所有写操作走 Route Handler / Edge Function，服务端持有 `service_role`。
2. **读操作可直连**。公开内容表的 SELECT 策略对 `anon` 开放，靠 RLS 白名单控制，页面首屏可并行取数。
3. **大模型不在浏览器直连**。`ARK_API_KEY` 只存在于服务端环境变量。
4. **3D 是装饰层，不是数据层**。WebGL 不可用时页面功能完全不受影响。

## 4. 渲染策略

| 路由 | 策略 | revalidate | 数据来源 |
|---|---|---|---|
| `/` | ISR | 300s | `stats`, `partners`, `news_posts`(3), `empower_modules` |
| `/about/*` | ISR | 3600s | `site_contents` |
| `/empower/*` | ISR | 3600s | `empower_modules` |
| `/agents`、`/agents/[slug]` | ISR | 600s | `agents`, `agent_categories` |
| `/market`、`/market/[slug]` | ISR | 600s | `market_items` |
| `/academy`、`/academy/courses/[slug]` | ISR | 600s | `courses` |
| `/news`、`/news/[slug]` | ISR | 300s | `news_posts` |
| `/traffic`、`/apply` | 静态 + 客户端表单 | — | `site_contents` |
| `/api/leads` | 动态（Route Handler） | — | 写入 `leads` |
| `/ops/leads` | 动态 + `no-store` | — | 直读 `leads` |
| `/api/og` | 动态 | — | `next/og` |

**查询约定**：

- 列表页筛选通过 `searchParams` 实现，RSC 内直接 `await params` 取值，不做客户端过滤。
- `generateStaticParams` 预生成详情页 slug 集合（智能体/资讯/课程各 ≤200 条，预生成成本可接受）。
- 静态参数 + ISR 的组合：新增内容走 `revalidatePath` 立即刷新，不等定时器。

### 5.2 索引与约束要点

- 所有列表页的过滤字段建索引：`agents(category, published, sort_order)`、`market_items(type, category, published_at desc)`、`news_posts(category, status, published_at desc)`。
- `leads.idempotency_key` 用**部分唯一索引**，避免历史空值互相冲突。
- `updated_at` 用 trigger 自动维护，避免各处漏写。

### 5.3 RLS 策略

```sql
-- 公开内容表：任何人可读。注意每张表的「可见性字段」不同，策略不能照抄
alter table site_contents      enable row level security;
alter table empower_modules    enable row level security;
alter table site_stats         enable row level security;
alter table agent_categories   enable row level security;
alter table agents             enable row level security;
alter table market_items       enable row level security;
alter table courses            enable row level security;
alter table news_posts         enable row level security;
alter table partners           enable row level security;

-- 有 published 布尔位的表
create policy "public read site_contents" on site_contents
  for select using (published = true);
create policy "public read empower_modules" on empower_modules
  for select using (published = true);
create policy "public read agents" on agents
  for select using (published = true);
create policy "public read market_items" on market_items
  for select using (published = true);
create policy "public read courses" on courses
  for select using (published = true);
create policy "public read partners" on partners
  for select using (published = true);

-- news_posts 用 status 而非 published
create policy "public read news_posts" on news_posts
  for select using (status = 'published');

-- site_stats 与 agent_categories 没有发布位（前者是全站指标，后者是固定分类字典）
create policy "public read site_stats" on site_stats
  for select using (true);
create policy "public read agent_categories" on agent_categories
  for select using (true);

-- 线索表：完全不开 anon 策略
alter table leads enable row level security;
-- 不创建任何 anon/authenticated 策略 → 浏览器直连一律被拒
-- 只有 service_role（服务端 SDK）可读写
```

> ⚠️ **易错点**：`site_stats`、`agent_categories` 没有 `published` 列，`news_posts` 用 `status` 而非 `published`。
> 策略里若照抄 `using (published = true)` 会直接建表失败；三张表必须用上面各自的写法。
> 建策略后应在干净库里跑一次冒烟：`select` 公开表 200，`insert` leads 被拒（见 T102 / 验收清单 6.3）。

**关键约束**：`leads` 表**不创建** anon 策略。这样即使有人拿到 anon key 直接 POST PostgREST，也写不进去。写入路径只有 `/api/leads`（Route Handler，用 `service_role`）。

### 5.4 `/ops/leads` 看板的访问控制

本期不做登录，用**双层**保护：

1. 中间件校验 `x-ops-token` 或 `?token=` 与环境变量 `OPS_TOKEN` 一致（`timingSafeEqual` 比较）。
2. 数据库侧走 `service_role` 读取，仅服务端执行，token 不出现在任何日志。

> ⚠️ 该方案安全性弱于账号体系，仅适用于运营内部、短期使用。**二期必须替换为 Supabase Auth + 角色表**（`ops_users` / `ops_roles`）。此项已登记在技术方案第 11 节「已知风险」。

## 6. 火山引擎（方舟）集成方案

### 6.1 定位边界（重要）

本期智能体为**纯展示 + 外链**，因此**不存在公开的大模型调用入口**。方舟的用途被限定在三个**不面向终端用户**的位置：

| # | 用途 | 面向 | 本期状态 |
|---|---|---|---|
| U1 | 资讯/内容 AI 辅助：标题、摘要、标签、SEO 描述建议 | 运营内部 | ✅ 实现（作为内部脚本/后台工具） |
| U2 | 供需语义匹配：`embedding` + 向量检索，为二期「智能匹配」铺路 | 系统内部 | ⚠️ 预留接口，默认不启用 |
| U3 | AIGC 素材生成（图片/视频），用于流量赋能展示与 OG 图备选 | 运营内部 | ✅ 实现（离线生成，落 Storage） |

**明确不做**：站内聊天、浏览器直连模型、把模型 API 暴露给第三方。

### 6.2 接入方式

- 端点：火山方舟 OpenAI 兼容接口 `https://ark.cn-beijing.volces.com/api/v3`
- 鉴权：`ARK_API_KEY` 环境变量，**仅服务端**
- 模型：默认 `doubao-seed-1-6`（文本），图像用 Seedream 系列，按可用性调整
- 封装：火山方舟客户端统一处理超时/重试/降级，业务层不直接调 SDK（该模块**二期预留、当前未实现**，规划路径 src/lib/ark/client.ts）

```ts
// src/lib/ark/client.ts（要点示意）
export async function arkChat(messages: ChatMessage[], opts?: {
  model?: string; temperature?: number; maxTokens?: number; timeoutMs?: number;
}) {
  // 1) 超时默认 8s（AbortController）
  // 2) 失败重试 1 次，指数退避 300ms

  // 4) 全程不打印 prompt 全文到日志（可能含业务敏感内容）
}
```

## 7. 3D / Shaders 动效方案

> 📎 **选型实测与组件清单见 `docs/04-shader选型指南.md`**（2026-10-20，esbuild + gzip 实测）。
> 本节为选型前的初版设计：§7.3 的背景层与 §7.4 场景 B 的实现路线，建议按选型指南的 M2/M3 条调整（评审通过后生效）。

### 7.1 总原则

> 3D 负责**气质**，不负责**信息**。任何一条信息都不能只有 3D 形式存在。

- 统一使用品牌色板作为 shader 调色输入，禁止彩虹色。
- 所有 3D 组件在 `<ShaderCanvas>` 内部实现降级，业务代码只调用一层组件。
- 首屏文字与 CTA **先渲染**，3D 画布异步挂载（`next/dynamic` + `ssr:false`）。

### 7.2 组件 API

```tsx
// src/components/three/ShaderCanvas.tsx
type QualityTier = 'high' | 'medium' | 'low' | 'static';

interface ShaderCanvasProps {
  scene: React.ComponentType;          // r3f 场景组件
  quality?: QualityTier;               // 手动指定，缺省自动探测
  dpr?: [number, number];
  className?: string;
  fallback?: React.ReactNode;          // 降级静态内容（品牌渐变 + 静态图）
  'aria-hidden'?: boolean;             // 默认 true
}
```

职责：
1. **能力探测**：尝试创建 `webgl2` → `webgl1` → 失败走 `fallback`。
2. **设备分级**：
   ```ts
   const dpr = Math.min(window.devicePixelRatio, 1.5);
   const mem = navigator.deviceMemory ?? 4;
   const conn = navigator.connection;
   const reduced = matchMedia('(prefers-reduced-motion: reduce)').matches;
   if (reduced || conn?.saveData || mem <= 2) return 'static';
   if (isMobile || mem <= 4) return 'low';
   if (dpr > 2.5 && isMobile) return 'medium';
   return 'high';
   ```
3. **帧率自适应**：`useAdaptiveQuality` 持续采样，60 帧滑动窗口内平均 <45fps 则降一档并降低粒子数。
4. **视口暂停**：`IntersectionObserver` 不可见时 `frameloop='never'`，省电省 GPU。
5. **卸载清理**：释放 geometry/material/texture，避免长页面滚动后显存泄漏。

### 7.3 场景 A：Hero「众智星云」

**视觉目标**：深藏蓝夜空 + 中心星云 + 大量微粒向心汇聚，暗示「集众智之力」。冷静、有层次，不炫技。

**技术实现**：

| 层 | 做法 |
|---|---|
| 背景层 | **改用 `@paper-design/shaders-react` 的 `MeshGradient`**（WebGL/GLSL，零运行时依赖，全库 11.6KB gzip）。`colors={['#142F59','#1D7FBA','#57B6A5','#1AA8D3']}` `distortion={0.8}` `swirl={0.15}` `speed={0.25}`，**省掉手写 FBM 背景层 GLSL**。需显式设 `minPixelRatio={1}`（默认 2）与 `maxPixelCount`（约 2,000,000）控移动端填充率 |
| 粒子层 | `THREE.Points` + 普通 `BufferGeometry`（N 个顶点 = N 个粒子，附加自定义 `aSeed` 属性）。**粒子是「点」不是「实例」**，此处不需要 `InstancedBufferGeometry`；`InstancedMesh` 只用于场景 B 的 8 个环节点。CPU 端仅在初始化时生成一次初始位置与随机种子 |
| 粒子运动 | **顶点着色器**内做运动：3D curl noise 场推力 + 向心引力 + 每粒子独立相位，避免 CPU 每帧回传位置 |
| 粒子外观 | 片元着色器画软圆点（`gl_PointCoord` 距离衰减），加色混合（`AdditiveBlending`），靠近中心的粒子更亮更大 |
| 深度 | `depthWrite:false`，`transparent:true`，靠颜色与亮度分层而非真实光照 |
| 交互 | 鼠标位置在 shader 内作为 `uPointer` 产生轻微引力偏移（±0.6 单位），不改变整体构图 |

**粒子数分级**：`high 32000 / medium 12000 / low 4000 / static 0`（走渐变背景 + 静态星点 PNG）。

**关键 shader 片段（示意）**：

> 语法说明：示例按 three.js 默认 **GLSL1** 书写（`attribute` / `varying` / `gl_FragColor`），WebGL2 上下文下同样可用。
> 若启用 `glslVersion: THREE.GLSL3`，需改为 `in` / `out`、`varying`→`in`+`out`、`gl_FragColor`→自定义 `out vec4 fragColor`。
> **两种版本必须二选一并全项目统一**，不要混用。

```glsl
// 顶点着色器
uniform float uTime;
uniform vec2  uPointer;
attribute vec3 aSeed;      // x: 初始相位, y: 噪声频率, z: 亮度权重

vec3 curl(vec3 p, float t) { /* simplex 3D 梯度做 curl，输出无散度场 */ }

void main() {
  float t = uTime * 0.12 + aSeed.x * 6.283;
  vec3 p = position;
  p += curl(p * aSeed.y, t) * 0.6;            // 噪声平流
  p += normalize(-p) * (0.35 / (length(p) + 0.6)); // 向心引力
  p.xy += uPointer * 0.06;                     // 指针引力
  vec4 mv = modelViewMatrix * vec4(p, 1.0);
  gl_PointSize = (6.0 + aSeed.z * 10.0) * (1.0 / -mv.z);
  gl_Position = projectionMatrix * mv;
}
```

**参数**：`uTime` 每帧更新；uniform 用 `useMemo` 缓存引用避免每帧重建材质。

### 7.4 场景 B：八大赋能能量环（P1）

> **实现路线已变更**，依据见 `docs/04-shader选型指南.md`（含 esbuild 体积实测）。
> 原方案用 `TorusGeometry` + `InstancedMesh` 实现 3D 环，**改为 2D shader**：
> 2D 光环用 3D 引擎无收益，且要额外叠一层 three 上下文与手写边缘光 shader。

- 方案：`@paper-design/shaders-react` 的 `PulsingBorder`（呼吸节点）或 `DotOrbit`（轨道点阵）。
- 8 个节点的亮度**直接绑 React state 的 props**，hover 高亮从「每帧改 uniform + 插值」降为「改一个 prop」，代码量降一个量级。
- 移动端继续降级为 CSS `conic-gradient` 光环（成本近零）。
- 若后续确认需要真 3D 环（绕 X/Y 轴倾斜），再回退到 `TorusGeometry` 方案。

### 7.5 场景 C：智能体卡片微动效（P1）

> **不使用 3D**。用 CSS `transform: perspective()` + `radial-gradient` 扫光实现，零 WebGL 开销、无掉帧风险。

```css
.agent-card { transform-style: preserve-3d; transition: transform .28s cubic-bezier(.2,.8,.2,1); }
.agent-card:hover { transform: perspective(600px) rotateX(6deg) rotateY(-8deg) translateZ(8px); }
.agent-card::after { /* 径向渐变扫光，hover 时移动 */ }
```

### 7.6 性能预算

| 指标 | 预算 | 手段 |
|---|---|---|
| 3D JS 体积 | **≤270KB gzip**（three+r3f 实测 **251.6KB** + Paper 层 **11.6KB**） | 动态导入，`ssr:false`；仅首页 Hero 异步加载 |
| 首屏 3D 挂载 | LCP 之后 / `requestIdleCallback` | 不阻塞首屏 |

> 📎 **体积数据实测更正（2026-10-20）**：原「≤180KB gzip」预算不可达。esbuild 实测 `three@0.186.1` + `@react-three/fiber@9.8.2`（具名导入 `BufferGeometry`/`ShaderMaterial`/`Points`/`Vector3` + `Canvas`/`useFrame`）打包后 **251.6KB gzip**（raw 940,233）；`@paper-design/shaders-react@0.0.81` 全库 **11.6KB gzip**（raw 35,227）。已上调至 **≤270KB**，完整实测表、复测记录与门禁做法见 `docs/04-shader选型指南.md` §0.1 / §1.1。

### 7.7 降级链（必须逐级可测）

> 现为**两套引擎**（Paper/WebGL 背景层 + three/WebGL2 粒子层），故降级链按引擎分叉修订。
> 完整修订版与逐级截图要求见 `docs/04-shader选型指南.md` §6；
> **2026-10-20 实测后的最终版与证据见 `docs/06-视觉方案与3D动效规范.md` §4.3**。

```
① WebGL2 可用 + 设备达 high/medium 档
   → Paper MeshGradient 背景层 + three 粒子层（12000 / 6000 粒子）
   ↓ ② WebGL2 可用但设备 low 档（移动端 / deviceMemory≤4 / 低端 GPU）
   → Paper 层降参数（speed↓、minPixelRatio=1、maxPixelCount 减半）
   → three 粒子层降到 2500 粒子
   ↓ ③ WebGL2 不可用（含「仅 WebGL1」的设备）
   → 静态品牌渐变 + 静态星点（CSS，无 WebGL）
   ↓ ④ prefers-reduced-motion / saveData / deviceMemory≤2
   → 同 ③（静态品牌渐变 + 静态星点）
   ↓ ⑤ JS 异常 / 未执行
   → SSR HTML 内已含静态渐变 + 文案 + CTA（完整可见）
```

> **⚠️ 2026-10-20 实测更正**：原 ③「仅 three（WebGL1）」**不可实现**。
> three r163 起移除了 WebGL1 支持（`WebGL1Renderer` 已删除；实测 `three@0.169.0`
> 构建产物中 `webgl2` 出现 3 次、`webgl1` **0 次**，并硬编码
> `const contextName = 'webgl2';`），Paper 同样需要 WebGL2。
> 故 WebGL1-only 设备**直接落到静态档**，③ 与 ④ 合并。

**统一硬约束**：

1. 任何一级降级，**Hero 文案、指标条、CTA 必须完整可见**（FR-HOME-01）。
2. 3D 负责气质，不负责信息；任何一条信息都不能只有 3D 形式存在。
3. fallback 与 canvas **必须等尺寸**（外层容器固定 `aspect-*` 或 `h-[100svh]`，canvas 绝对定位铺满），否则产生 CLS，违反 FR-SITE-05 的 CLS ≤0.1。
4. 每级降级都必须**截图留证**。

**两道防线（2026-10-20 新增）**：

| 防线 | 实现 | 覆盖 |
|---|---|---|
| 严格 WebGL2 探测 | `quality.ts` 的 `detectWebGL2()` 只认 `'webgl2'` | 探测为「有 WebGL2」但实际创建上下文失败（驱动黑屏、上下文丢失、显存不足、Paper 组件内部异常） |
| 错误边界 | `src/components/three/ThreeErrorBoundary.tsx` | 上述全部运行时异常 → 降级为静态背景，**内容不受影响** |

> 修复前，WebGL1-only 设备上 three 抛 `THREE.WebGLRenderer: Error creating WebGL context.`，
> 异常沿 React 树冒泡把**整个 Hero（含 H1 与 CTA）一起卸载**。这正好命中竞品审查 R5
> 点名的微信内置浏览器 / 老旧设备场景。现已用「严格探测 + 错误边界」双重兜住，
> 逐级实测结果见 `docs/06` §4.3 表格。

**可观测性**：`HeroScene` 根节点暴露 `data-3d-tier` / `data-3d-particles`，
降级档位与实际粒子数可被自动化脚本直接读取。

## 附录 A · 渲染方式与 SEO 约束（2026-10-20 实测补充）

### A.1 关键约束：动态渲染会让 metadata 掉进 `<body>`

Next.js App Router 在页面走**动态渲染**时，会把 `<title>` 与 `<meta>` 一并 flush 到 `</body>` 之后。实测：

| 页面 | 渲染方式 | `</head>` 位置 | `<title>` 位置 | 结果 |
|---|---|---|---|---|
| `/agents`（原） | 动态（`await searchParams`） | 955 | 66083 | ❌ 搜索引擎读不到 |
| `/market`（原） | 动态 | 955 | 27477 | ❌ |
| `/news`（原） | 动态 | 953 | 22933 | ❌ |
| `/market/[slug]`（原） | 动态（缺 `generateStaticParams`） | 1120 | 24109 | ❌ |
| `/agents/[slug]` | SSG（有 `generateStaticParams`） | 2148 | 908 | ✅ |
| `/` `/about` `/apply` 等 | 静态 | — | < 1200 | ✅ |

**结论与规则**：

1. **面向搜索引擎的页面必须静态化**（`○ Static` 或 `● SSG`）。当前构建产物中除 API 路由与内部后台页外，**全部为静态/SSG**。
2. **动态路由必须提供 `generateStaticParams`**（`/agents/[slug]`、`/market/[slug]`、`/news/[slug]`、`/academy/courses/[slug]`、`/empower/[slug]` 均已提供）。
3. **需要按查询参数筛选的列表页**，采用「服务端渲染全部条目 + 客户端过滤」，而非服务端 `await searchParams`。实现见 `src/components/ui/FilterRoot.tsx` 与 `FilterLink.tsx`。
4. 唯一保留动态渲染的是 `/ops/leads`（内部后台，`robots: { index: false }`，本就不需要被索引）。

### A.2 浅底文字的可读性分层

品牌主色 `#1D7FBA` 在白底仅 **4.38:1**，达不到 WCAG AA 正文 4.5:1。浅底上的小字与填充按钮统一改用品牌渐变起始色 `#0968AB`（**5.87:1**），主蓝保留给边框、图标与 ≥24px 的大字。完整对比度实测表见 `docs/06-视觉方案与3D动效规范.md` §2.3。

### A.3 数据库迁移的实测结论（2026-10-20，真实 PostgreSQL 16.14）

迁移脚本此前从未在任何 PostgreSQL 实例上执行过。本轮起了一次性集群（`initdb` + `pg_ctl` + `psql -f` 逐字执行），并新增了可复跑的冒烟测试 `supabase/tests/001_migration_smoke.sql`（**27 条断言**）。实测结论：

| # | 发现 | 性质 | 处理 |
|---|---|---|---|
| 1 | `news_posts` / `market_items` / `courses` 的正文列是 `body_md text`，而应用类型是 `body: string[]`、页面直接 `post.body.map(...)` | **会打挂线上页面**（接真库即 `undefined.map`） | 统一为 `body jsonb not null default '[]'::jsonb`；`0001` 同步修改，新增 `0003_body_jsonb.sql` 作为老库升级路径（按空行把 `body_md` 切成段落数组） |
| 2 | 迁移里**没有显式 GRANT** | 换自建 Postgres 会全线 permission denied | `0002_rls.sql` 补显式 grant：`anon`/`authenticated` 只授予 10 张公开内容表的 SELECT，**`leads` 一列都不给**；`service_role` 给全部表与**全部序列**（bigserial 主键插入需要序列 USAGE，否则报 `permission denied for sequence leads_id_seq`） |
| 3 | `leads` 表零策略 | 符合设计，但**仅靠「没授权」不足以证明安全** | 冒烟测试分两层验证：① 未授权层（permission denied）② **兜底层**——临时授予 anon INSERT + 序列权限后，写入仍被 `new row violates row-level security policy for table "leads"` 拦住 |
| 4 | `route.ts` 插入的 13 个列全部存在于 `leads` | 一致 | 由 `test/db-schema-contract.test.ts` 锁死（解析迁移 SQL + 解析 route.ts 的 insert 字段） |
| 5 | `agents.category` 有外键指向 `agent_categories(slug)` | 设计如此 | 冒烟测试的测试数据需先建分类行 |

**两条路径均已验证**：全新安装（新 `0001`+`0002`）与老库升级（旧 `0001`+新 `0002`+`0003`）跑完冒烟测试都是 **27/27 通过、退出码 0**，且升级后的表结构与全新安装**列名集合完全一致**（仅列顺序不同，`add column` 追加所致，不影响按名取值）。

> **方法论要点**：本地「未配置 Supabase → 回落到种子数据」的兜底，会把**列名错配、类型不匹配、约束不生效**这一整类问题全部掩盖。2026-10-20 的 `body_md` 错配就是典型——本地开发一切正常，一旦接真库，新闻详情页直接抛错。因此数据层契约必须有**不依赖运行时环境**的静态校验（`test/db-schema-contract.test.ts`）+ **真实数据库的行为校验**（`supabase/tests/001_migration_smoke.sql`）两道防线。
