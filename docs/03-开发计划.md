## 2. 关键路径

```
M0 工程基建
  └─▶ M1 数据与种子
        └─▶ M2 核心页面
              ├─▶ M3 智能体/供需 ─┐
              └─▶ M4 学院/动态  ──┴─▶ M5 留资管线 ─▶ M7 上线
                    └─▶ M6 3D 动效（可与 M2–M4 并行）┘
```

**必须串行的**：M0 → M1 → M2。数据模型没定死，后面全部返工。
**可以并行的**：M6（3D）与 M3/M4（页面），只要 M0 的依赖装好。

### B.4 列表页渲染方式修订（SEO 缺陷修复，2026-10-20）

**缺陷**：实测发现 `/agents`、`/market`、`/news` 三个列表页的 `<title>` 与 `<meta name="description">` **被渲染到了 `</body>` 之后**（`</head>` 在第 955 字节，`<title>` 在第 66083 字节）。原因是这三个页面在服务端 `await searchParams`，页面走**动态渲染**，Next.js 会把 metadata 一起 flush 到流末尾——**搜索引擎读不到，Lighthouse 的 meta-description 判 0 分**（SEO 94→91）。

**同类对照**：`/agents/[slug]`（有 `generateStaticParams`）正常；`/market/[slug]`（无）异常——证实是「静态 vs 动态」而非组件写法问题。

**修订**：

| 页面 | 原实现 | 现实现 |
|---|---|---|
| `/market/[slug]` | 动态渲染 | 加 `generateStaticParams`，与 `/agents/[slug]` 对齐 |
| `/agents` `/market` `/news` | 服务端 `await searchParams` 后过滤 | **服务端渲染全部条目**，筛选在客户端执行 |

客户端筛选由两个共享组件承担：

- `src/components/ui/FilterRoot.tsx` —— 读取 URL 查询参数，按 `[data-filter-key]`（分类）与 `[data-filter-text]`（关键词）控制条目显隐，并同步选中态与结果计数；
- `src/components/ui/FilterLink.tsx` —— 筛选按钮用 `history.pushState` 改 URL 并广播事件，**不触发整页刷新**（避免「全部条目 → 过滤后」的闪烁），同时保留真实 `href` 以便无 JS 时可用。

**权衡说明**：筛选变体本就以 `alternates.canonical` 指向不带参数的规范地址，**本就不是独立可索引页**，因此「服务端渲染全部条目 + 客户端过滤」不损失任何索引价值；相反，它让全部条目内容完整落在 HTML 里，对 SEO 是净收益。

**验收（已实测）**：`/agents?category=office` → 29 项中显示 4 项；`?q=midjourney` → 命中 1 项；`/market?tab=supply` → 8 项中显示 4 项；`/news?category=活动` → 4 项中显示 1 项；点击分类按钮 URL 即时更新且**页面未重载**（`window.__noReload === true`）。全部 18 个公开页面的 `<title>`/`<meta description>` 现已确认落在 `</head>` 之内。
