# 官网 UI 与性能优化

日期：2026-10-21。范围：公开官网页面、共享界面与装饰动效；不改变留资接口、数据库及运营后台逻辑。

## 设计方向

保留 `logo.svg` 的蓝、藏蓝与青绿色。首页采用具有清晰轮廓的汇聚粒子视觉，正文采用开放式排版、细分隔线和不等宽布局。减少重复阴影卡片、玻璃底、泛光和居中标题；品牌、内容和主要行动优先。

- 首页：重排首屏、数据、服务与社区动态，八项服务保持可达。
- 内页：统一页头、标题间距、按钮与卡片层级；兼顾目录、详情和申请表单。
- Shader：复用可见性控制、设备分级和静态降级；视口外与后台暂停。
- 性能：装饰延后加载、移动端限制像素比、指针使用 ref、移除不必要的动效依赖。

## 验收要求

1. 375、768、1024、1440 宽度布局无横向溢出，导航、筛选与主要链接可用。
2. 无 JS、无 WebGL2、减少动态效果和省流量场景仍有完整标题、正文、CTA 与静态视觉。
3. 动态视觉有统一可见状态，离屏及后台停止渲染；移动端粒子 DPR 不超过 1.25。
4. 类型检查、原有测试与生产构建通过，独立代码复核后修复实际问题。
5. 性能结果注明测试条件；本机缓存、无节流或种子数据结果不等同于公网速度与线上业务验收。

### 体积与性能

| 项目 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---|
| 页面中 WebGL 画布 | 2 | **1** | −1（背景层与粒子层合并到同一上下文） |
| 浏览器实际加载静态 JS encoded 合计 | 386,578 B | **372,589 B** | −13,989 B（−3.6%） |
| LCP（375×812 视口、禁用缓存、连续 3 次刷新） | 68 / 64 / 64 ms¹ | **146 / 110 / 94 ms**（中位数 110 ms）¹ | 不可直接比较¹ |
| CLS（同样条件） | 0.00665 | **0.00 / 0.00 / 0.00** | ✅ |
| 指标条 | 客户端 framer-motion 计数 | **server component 静态输出** | 去掉一整个客户端依赖与动画 |

¹ **测量方法不同，不可直接比较**：基线用的是内置浏览器的 `PerformanceObserver`，本轮用 DevTools **trace 插桩**（插桩本身有开销，且会改变资源加载时序）。两组数字各自内部可比，但**跨组比较无意义**。要得到可比结论，需用同一方法在两个版本上各测 3 次。

> ⚠️ 本轮**没有**在真实公网环境或真实 Supabase 数据下测量。种子数据比真实库小，接真库后首屏数据量、查询耗时与真实线索量都会影响结果。**上线后应以真实环境的 Lighthouse / RUM 数据为准**，本节数字仅用于本机版本间比较。

### 独立复核发现并已修复

| 问题 | 修复 |
|---|---|
| `ShaderCanvas` 首次渲染降级内容时未挂载 ref，观察器只运行一次，后续画布无法正确离屏暂停 | 观察器移到**常驻的场景外壳**上（`useSceneActivity`），降级静态视觉期间也持续观察 |
| 指针移动每帧 `setState`，触发整树重渲染 | 改为 `pointerRef`，逐帧只读 ref，不再触发 React 更新 |
| 移动端 DPR 未真正应用 | 统一在 `profileDevice` 计算并下传到 Canvas |
| 上层未控制离屏/后台暂停（Paper 内部已有自己的暂停，两套机制冲突） | 合并为**单一 Canvas + 单一可见状态**，由上层统一控制 |
| 原型方案会卸载 Paper 的暂停动画、忽略画像 DPR、质量采样未暂停 | 均未采用，按实际生命周期重写 |

## 搜索能力与结构化数据轮次（2026-10-21）

三条 FR（FR-SITE-03 / FR-MARKET-07 / FR-SITE-08）一次交付，核心是**把「同一个功能三处三样」收敛到一个共享原语**：
`src/components/ui/SearchField.tsx` 是全站唯一的搜索输入框，供需页、智能体页、全局搜索页三处复用。

### 实测结果

| 项 | 结果 |
|---|---|
| 构建 | `pnpm build` → 74 个静态页；`/search` 为 `○ (Static)`、`/api/search` 为 `ƒ (Dynamic)` |
| 测试 | `pnpm test` → **178 pass / 0 fail**（新增 2 个契约测试文件） |
| 响应式 | **72/72 组合 0 问题**（18 页 × 4 断点，审计清单已加入 `/search`） |
| Lighthouse | 首页、`/search`（桌面 + 移动）、`/market`、`/agents`、`/apply`、资讯详情页均 **100 / 100 / 100 / 100**（每页 54–57 项通过、0 失败） |
| metadata | 66 个公开页面（含 54 个动态页）的 `<title>`/`<meta description>` **全部落在 `<head>` 内**（判定方法：比较 `index('<title>')` 与 `index('</head>')`，前者必须更小；字节偏移随文案变动，不作固定值引用） |
| 结构化数据 | 16 个含面包屑的路由全部带 `BreadcrumbList`（66 个公开页面中的 65 个；首页不带，符合预期）；`position` 连续、`item` 为绝对 URL、末级按 Google 规则省略 `item` |
| 搜索行为 | 实测**纯客户端过滤**：输入后 URL 即时更新、**页面未重载**（`window.__probe` 存活）、历史记录不膨胀（`history.length` 保持 2） |
| 切分类不丢词 | `/search?q=智能体定制` → 点「供需」chip → URL 变为 `?type=market&q=智能体定制`，搜索词保留（修掉了 `FilterLink` 丢参数的缺陷） |
| 接口 | `/api/search` 全量 46 条（智能体 29 / 需求 4 / 供给 4 / 课程 5 / 动态 4）；`?q=` 与 `?type=` 均生效；出错返回 500 + `error`，不假装空结果 |

### 本轮修掉的真缺陷

| 缺陷 | 根因 | 修法 |
|---|---|---|
| 搜「智能体」一条都搜不到（实测只命中 1 条供需） | 29 个智能体条目的标题/摘要/标签里没有「智能体」三个字，**类型名没进可检索文本** | 类型入口词（逐条计算：需求方「供需 需求」、供给方「供需 供给」）与长描述（智能体简介、正文段落）一并进入可检索文本；搜「需求」不会把供给方带出来 |
| **同一关键词在三个搜索框结果不同**（独立复核发现） | `/market`、`/agents` 各自拼自己的 `data-filter-text`，与全局索引的语料不一致 | 抽出 `src/lib/search/items.ts` 统一投影：列表页与全局索引用**同一个** `searchItemText()`；实测 `/market` 搜「需求」由 0 条变 4 条、`/agents` 搜「智能体」由 0 条变 29 条、`/agents` 搜「办公」由 2 条变 4 条 |
| `/search` `/market` 未标注示例数据 | 两个页面直接说「46 条公开内容」，而这 46 条全部出自种子数据 | 与 `/agents`、`llms.txt` 同一口径标注「示例内容」；`/market` 额外说明发布方已匿名化 |
| 全站表单控件的 `text-[14px]` 静默失效 | `globals.css` 把 `button, input, textarea, select { font: inherit; }` 写在**层级外** —— Tailwind v4 里未分层样式优先级高于 `@layer utilities` | 收进 `@layer base`；实测 `input` 与 `div` 字号从此一致 |
| 搜索输入框只有 23px 高（< WCAG 2.5.8 的 24px） | 输入框没撑满 40px 容器，上下缘是点不到的死区 | 输入框加 `h-full`；72 组合审计归零 |
| 筛选计数小字对比度 3.7:1（Lighthouse 判失败） | `opacity-70` 压暗，同一色值压不住白底与蓝底 | 改为按选中态分别给色（浏览器实测：白底 5.62:1 / 蓝底 4.93:1），`/search`、`/market`、`/agents` 统一用 `.filter-count` |
| Course 结构化数据 `courseWorkload` 误用 | schema.org 的 `courseWorkload` 是 ISO-8601 时长字段，却被填了「导师：…」 | 改用 `instructor: { '@type': 'Person', name }`；同时把 `courseMode` 从 `online` 改为 `onsite`（原值与页面可见文案「线下授课 + 项目制实战」矛盾） |
| Article 结构化数据缺 `image` | Google Article 富媒体需要代表性图片 | 用站内动态 OG 图按本条标题生成（不编造不存在的照片） |
| 品牌副标对比度 4.4:1（**滚动态**才暴露） | `.header-brand-latin` 用 `opacity: .65`，页头滚动后变实底（navy 字 on 白底）→ #677893 只有 4.4:1，差 0.1；深色页头下却是白字，一直达标 —— 所以它**只在滚动后出现**，Lighthouse 分数会在 96/97/99/100 之间抖动 | opacity 提到 `.7`：浏览器实测实底态 5.24:1、深色态 7.32:1，两种状态都达标 |

> **分数抖动也要追**：本轮 Lighthouse 曾出现 96/97/99/100 的抖动，一度以为是测量噪声。
> 实际是 `.header-brand-latin` 的对比度**只在页头滚动成实底时才不达标**（4.4:1，差 0.1）——
> 深色页头下它是白字、一直达标。修掉之后，6 个页面连测全部稳定 100。
>
> **独立复核的价值**：本轮第一次提交时，统一性只做到了 **UI 层**（三处计算样式完全一致），
> 但**检索语料仍然分叉** —— 同一个词在三处得到不同结果。这说明「统一」不能靠视觉对齐，
> 必须把**数据投影**也收敛到同一个函数；已由 `test/global-search.test.ts` 的
> 「列表页与全局索引的检索语料逐字相同」用例锁死。
