# 区块运行时化契约（方式一：DB 优先、烘焙兜底、后台保存即时失效）

> 代码事实源：`src/lib/opc/blocks-runtime.ts`；契约测试：`test/dynamic-blocks.test.ts`。
> 与 `docs/14-动态内容契约.md`（新闻/活动**列表**的构建期占位符模式）互补：
> 本文档覆盖的是**烘焙区块的就地替换**模式——目标区块没有占位符，
> 页面结构直接来自 `generated/pages.json` 快照，运行时在快照 HTML 上做确定性替换。

## 1. 模式总述

```
请求 → ISR 缓存（300s）→ 未命中/过期 → getRuntimeReplicaPage(pathname)
                                        ├─ getReplicaPage 取烘焙快照
                                        ├─ 按区块查 DB（表级查询，无用户输入拼接）
                                        ├─ 查到非空行 → applyXxx 在快照 HTML 上替换区块
                                        └─ 未配库/异常/空表/结构失配 → 原样返回烘焙内容
后台保存 → resource-api 写库成功 → revalidatePath(目标页) → 下一次请求即再生成
```

三档兜底语义（区块级，互不牵连）：

| 状态 | 行为 |
|---|---|
| 未配置 Supabase / 查询 error / 查询 throw | loader 返回 null → 不替换，烘焙内容完整保留 |
| 查询成功但结果为空（或过滤后为空） | 不替换，烘焙内容完整保留 |
| 替换过程抛异常（数据形状意外） | 装配层 try/catch 兜底 → 整页回落烘焙，**永不 500** |

## 2. 区块清单（页面 × 表 × 锚点 × 失效链）

| 页面 | 区块 | DB 表 | 快照锚点（须恰好出现一次） | admin 模块 → revalidatePath |
|---|---|---|---|---|
| `/` | hero 统计数字墙 | `site_stats` | `div.hero-stats-row` | 统计数字 → `/` |
| `/`、`/market`、`/work` | 伙伴墙（三页共用同一函数） | `partners` | `ul.opc-visual-partner-grid` | 合作伙伴 → `/`、`/market`、`/work` |
| `/center` | 课程方向卡 | `courses` | `div.opc-academy-course-grid` | 课程 → `/center` |
| `/agent` | 目录（chips + 分区 + 卡） | `agents` | `div.filter-scroll`、`div[data-opc-agent-results]` | 智能体 → `/agent` |
| `/market` | 供需卡（供给/需求两区各自替换） | `market_items` | `div.supply-grid`、`div.demand-grid` | 供需 → `/market` |

页面装配：`/`、`/center`、`/agent`、`/market`、`/work` 均为**显式 ISR 300 路由**，
与 `/newslist` 同款结构（reference-blue.css → 双类名容器 → 内容 → ReplicaInteractions → HashRouteBridge）；
其余复刻页继续走 catch-all 的纯快照渲染。

## 3. 替换算法：括号配平（replaceBalancedBlock）

- 定位：正则命中开标签 → 从开标签之后按 `<div`/`<ul` 字面 token 计数配平到闭标签；
  只替换**区块内部**，开闭标签本身（含其上的 class/style/aria 属性）原样保留。
- 前提（由 `test/dynamic-blocks.test.ts` 的守卫测试锁定）：
  1. 各锚点在对应页 HTML 中**恰好出现一次**；
  2. 页面 HTML 的 `<div`/`<ul` **字面出现次数 == 真实标签数**（无注释、无属性值藏 token）。
  上游再生成产物若破坏前提，CI 先红，替换不会静默失准。
- 闭标签缺失（结构不完整）→ 原样返回，宁可不动不可截断。

## 4. 各区块交互与渲染契约

### 4.1 首页统计墙
- 卡结构：`div.hero-stat > span.hero-stat-num + span.hero-stat-lbl`，带 `data-v-af8bee70` 作用域属性。
- 数值口径：`value` + `suffix`（`+` 等符号型紧贴数字，文字型补空格）。
- 数字滚动动画（visual-motion 的 `parseStatNumber`）按「纯整数 + 非数字尾缀」解析，兼容上述口径。

### 4.2 伙伴墙
- **整墙接管语义**：DB 有 ≥1 行合法数据即整墙替换为 DB 名单（不是与烘焙 16 家合并）。
- 卡结构：`li.opc-visual-partner-card > img.opc-visual-partner-logo`（alt=名称）。
- **必须带合法 `logo_url` 才渲染**（https 外链或本站根相对路径）；无 logo 的行跳过——
  设计层没有文字卡样式，宁缺毋滥。

### 4.3 课程方向卡
- 卡结构照抄烘焙卡（`figure.opc-academy-course-card` 三层）。
- 配图回落链：合法 `cover_url` > 同 `track` 的烘焙配图 > 首张烘焙配图 > 无图。

### 4.4 /agent 目录
- **两级替换**：侧栏 `filter-scroll`（chips）与 `data-opc-agent-results`（状态行 + 分区）整体重建。
- 分类 label 取 `src/lib/site/config.ts` 的 `agentCategories`（与后台表单选项同源）。
- 筛选契约：ReplicaInteractions 的 `filterGrid` 按 `data-opc-categories`（HTML 转义 JSON 数组，
  DOM 属性读取时 `&quot;` 自动解码）与 chip `data-opc-value` 做 **NFKC 归一化精确匹配**；
  空分区按 `data-opc-agent-group` 隐藏；状态行文案 `共 N 个智能体`。
- 卡片必须带 `tc-glare` 与 `tc-border-glow` **两个**装饰节点（后者 CSS 默认可见，缺失少边框光晕）；
  右下角箭头装饰 `tc-link` 从烘焙 HTML 提取复用。
- 外链仅 `https`（`isSafeExternalUrl`），不合法的行整卡跳过。

### 4.5 /market 供需卡
- **分区各自替换**：`supply-grid` 有 DB 行才换供给区，`demand-grid` 同理——可只录一边。
- DB 卡**不带** `data-opc-action="navigate"` 详情动作（无对应详情页）；「联系合作」固定指向
  `/opcapply?formType=partner`（与烘焙卡一致）。
- 日期口径：`marketDate` 用 `Intl + Asia/Shanghai` 取**日历日**（`timestamptz` 直接截 UTC 会把
  北京 0–8 点录入的显示成前一天），输出 `YYYY/M/D` 无前导零，与烘焙一致。
- 供给/需求 tab 切换与 load-more 分页不依赖卡片内部结构，DB 卡自动参与。

## 5. 安全口径

- 所有 DB 文本（标题/摘要/名称/标签/分类）渲染前一律过 `escapeText`（`& < > " '` 全套）。
- 图片 URL：仅 https 外链或本站根相对路径（拒 `//`、控制字符、反斜杠）；
  智能体外链同口径（拒 http/userinfo）。
- 查询全部为静态表名/列名的表级查询，无用户输入拼接。
- 已知口径差（低风险，待后台收紧）：admin `optionalUrl` 允许 http，前台只渲染 https——
  存了 http 图/链接的行会被静默跳过。

## 6. 已知边界

- `site_contents`（内容块）表仍无前台消费方——后台可维护但无页面展示。
- `/webnew/index.html` 遗留别名仍渲染烘焙版首页（与 `/` 的运行时版不一致）。
- Next ISR 构建缓存跨构建复用：`.next/cache` 内 ISR 页在 revalidate 窗口内不会被下一次
  `next build` 重渲染——**改库后验证必须删除构建目录全新构建**（部署不受影响：线上由
  revalidatePath + ISR 驱动）。
